## 3. 问题清单

### P0-1 · 生产 CSP 打断全部内联样式驱动的可视化

**现象**：`vercel.json` 声明的 `style-src 'self'` 不含 `'unsafe-inline'`。CSP3 中内联 `style` 属性由 `style-src-attr` 管辖，并回退到 `style-src`，因此**所有通过模板字符串写进 `innerHTML` 的 `style="..."` 都会被浏览器拒绝应用**。

**实测证据**（用 `vercel.json` 的原始响应头托管 `dist/`，Chromium 加载）：

```json
{
  "cspViolationCount": 138,
  "cspViolations": [
    { "directive": "style-src-attr", "blockedURI": "inline" },
    { "directive": "font-src", "blockedURI": "data" }
  ],
  "probes": {
    "subjectBar": { "inlineAttr": "height:0%; --bar:#13785f", "computedHeight": "auto" },
    "inlineStyleAttrCount": 44
  }
}
```

**对照实验**（同一份产物，唯一变量是有无 CSP 头）：

| 条件 | 注入 `<div style="width:123px;height:45px">` 后的计算样式 |
| --- | --- |
| 带 CSP | `1440px / 0px`（**被拒绝**），违规 138 处 |
| 去掉 CSP | `123px / 45px`（正常应用），违规 0 处 |

**影响面**：`src/app.js` 有 14 处 `style="..."`，渲染后页面上出现 44 个内联样式属性，覆盖：

| 位置 | 元素 | 后果 |
| --- | --- | --- |
| `app.js:3649 / 3792 / 4901 / 5716 / 5747 / 5884 / 6521` | `.progress-fill` | 所有进度条填充宽度失效 |
| `app.js:3820 / 5847` | `.ring` | 环形图 `--value` 归零 |
| `app.js:3849` | `.subject-bar-fill` | 科目柱高度与配色失效 |
| `app.js:3470 / 3877 / 6414` | 热力图 / 趋势柱 / 滚动窗口 | 柱高失效 |
| `app.js:4225` | 未命名进度条 | 失效 |

**根因**：`v4.1.0` 新增安全响应头时只做了静态校验（上一轮 RISK-03 已注明"未线上验证"），而项目的可视化大量依赖内联样式，两者直接冲突。

### P0-2 · 生产 CSP 拦截 3 个内联 `data:` 字体

**证据**：`dist/assets/index-*.css` 中含 3 处 `data:font/woff2;base64,...`（合计约 12.5 KB base64）。`font-src 'self'` 不放行 `data:`，浏览器报 `Loading the font 'data:font/woff2;base64,...' violates ... "font-src 'self'"`。

**根因**：Vite 默认 `build.assetsInlineLimit` 为 4 KB，小于该值的字体切片被内联进 CSS。构建产物目录下 103 个 woff2 中有 3 个未落盘（被内联）。

**影响**：这 3 个 `unicode-range` 覆盖到的汉字会回退到系统字体，在同一段落里出现字形不一致。属于"部分字符渲染异常"，不易被肉眼归因。

### P1-1 · 第二套状态存储随生产包发布，且与 `app.js` 共用同一个 localStorage 键

这是本轮**最隐蔽**的发现。

**证据链**：

1. `src/ui/density-controller.js` 是生产模块（`app.js` 导入它），它 `import { StateManager } from '../core/state-manager.js'`。
2. 用未压缩构建（`--minify false`）检索特征串，`state-manager.js` 与 `event-bus.js` **确实在 `app-*.js` 中**：

```text
reviews.queue          -> app-*.js     (state-manager.js 独有字面量)
tableName:recordId     -> app-*.js     (state-manager.js 独有字面量)
getDensityMode         -> app-*.js
state:changed          -> app-*.js     (event-bus.js)
calibration:tierFallback -> app-*.js   (event-bus.js)
```

3. `src/core/state-manager.js:14`：`const STORAGE_KEY = STORAGE_KEYS.APP_STATE;` —— 即 `pku_swm_420_dashboard_v3`，**与 `app.js` 的主状态键完全相同**。
4. `state-manager.js:483`：`let state = loadState();` —— 模块导入即在初始化时读取并解析该键。
5. `state-manager.js:200`：`saveState(state)` 会把**自己的内存副本**（页面加载时读到的快照，之后永不刷新）序列化写回同一个键。

**为什么现在没有出事**：`applyDensityMode(mode)` 的 `else` 分支 `normalizeDensityMode(mode, getDensityMode())` 会**急切求值** `getDensityMode()`，所以每次应用密度都会走一次 `StateManager.getState()`——但它只读不写。而唯一会写的 `setDensityMode()` 未被任何生产路径调用，已被 tree-shaking 移除（产物中检索不到）。

**为什么这是地雷**：只要将来有任何一行代码调用 `StateManager.setState(...)`（例如把 `initDensityMode()` 接进 `bindDensityControls`），它就会把页面加载时的旧快照整体覆盖回 `pku_swm_420_dashboard_v3`，**静默丢掉用户本次会话写入的全部记录**。同时它还会写 `pku_swm_420_dirty`（`STATE_DIRTY_MAP`），与 `app.js` 的离线队列语义重叠。

**附带代价**：每次首屏都会把整份状态 JSON 多解析一遍（`loadState()`），并多带 744 行代码（state-manager 605 + event-bus 139）进 `app` chunk。

### P1-4 · `app-imports.test.js` 是"变更探测器"而非"回归探测器"

| 指标 | 实测 |
| --- | --- |
| 文件行数 | 2,671 行 |
| 文件字节 | 177,615 |
| `readFileSync` 调用 | 85 处 |

### P2-2 · `router.js` 的路由 ID 与 `route-contract.js` 不一致

README 声明"路由 ID 与移动端主入口统一定义在 `src/core/route-contract.js`，不要在视图或事件处理器中另建路由列表"，但 `src/core/router.js:17-28` 自建了另一套：

**1-A 内联样式（二选一）**

- **最快（1 行）**：`vercel.json` 的 CSP 改为 `style-src 'self' 'unsafe-inline'`。
  - 理由：XSS 的主要攻击面是 `script-src`，此处仍保持 `'self'` 且无 `'unsafe-eval'`；`style-src` 放宽的实际风险很低（样式注入无法执行脚本）。
  - 代价：放弃了"完全禁内联"的严格姿态。

- **正确（推荐，约 14 处改动）**：把 `style="..."` 从模板字符串里拿掉，改为渲染后经 CSSOM 写入。
  - **已实测可行**：`el.style.setProperty('--value', '75')` 与 `el.style.width = '50%'` 在 CSP 下**正常生效**（CSP 只管辖标记中的 `style` 属性与 `<style>` 元素，不拦 CSSOM 赋值）。
  - 具体做法：模板里改输出 `data-fill="75"` / `data-value="75"` / `data-bar="#2868a8"`，在渲染收尾处统一遍历一次批量 `setProperty`。这样既保住严格 CSP，也顺手消掉 44 个内联属性。

**1-B `data:` 字体（二选一）**

- 改 CSP：`font-src 'self' data:`。
- 或改构建（更干净）：`vite.config.js` 加 `build: { assetsInlineLimit: 0 }`，让 3 个字体切片落盘为独立文件——顺带减小 `index.css` 体积（当前 370.91 KB / gzip 86.55 KB，预算上限 95 KB，已经很接近）。
