# 项目审计与改进建议

审计日期：2026-08-17。

本文记录当前代码边界、已经完成的清理、暂不删除的迁移代码，以及后续架构和产品改进顺序。它用于避免维护者再次并行扩展两套实现。

2026-09-15 备注：本文数字已按当日代码校正，架构结论与迁移顺序仍然有效；门禁现状与技术栈成熟度见 [TECH_AUDIT_2026-09-15.md](TECH_AUDIT_2026-09-15.md)，本轮修复项与验收记录见 [REMEDIATION_2026-09-15.md](REMEDIATION_2026-09-15.md)。

## 当前结论

- 当前生产入口为 `index.html -> src/main.js -> src/app.js`。
- `src` 下现有 43 个 JavaScript 模块；当前生产链路与已测试的渐进模块化层仍同时存在，未接管模块不能按“未引用”直接删除。
- `src/app.js` 7,132 行，仍同时负责状态迁移、同步编排、表单绑定、路由和大部分渲染，是最高风险文件。
- `src/styles/base.css` 约 9,151 行；`src/styles/workspace.css` 和 `src/styles/components/toolbar.css` 是后置视觉层。三者的加载顺序目前属于运行契约。
- `index.html` 同时承载全部页面骨架，页面新增字段会跨 HTML、`app.js` 和 CSS 三处修改。
- 现有 39 个测试文件、679 项测试和五档宽度 Chromium 冒烟测试可作为渐进迁移的回归基线。

## 本轮已完成

- 根目录历史实现已迁入 `src/data`、`src/infrastructure`、`src/styles` 和 `src/ui`，旧路径不再保留重复副本。
- 长期计划文档迁入 `docs/STUDY_PLAN.md`。
- 存储键和同步表名分别集中到 `storage-contract.js` 与 `sync-contract.js`。
- 路由 ID 和移动端主入口集中到 `route-contract.js`，生产路由校验与测试共用同一份契约。
- 删除生产与迁移模块中的未使用函数、导入、映射、赋值和测试生成器。
- 删除只做语法解析且漏检 `scripts/` 的 `check-js.mjs`，改由 ESLint 检查未使用代码、未定义变量和常见逻辑错误。
- Vite 归入开发依赖；运行依赖只保留 Supabase SDK 与 Lucide。
- 生成目录由 `npm run clean` 统一清理，不提交构建、截图和浏览器会话产物。
- 导航事件收敛为单一委托入口，避免导航按钮和跨页跳转按钮重复绑定。
- 移动端底栏收敛为四个高频入口加“更多”，隐藏路由通过“更多”的选中态和可访问标签反馈当前位置。
- 移动端主内容改为独立滚动视口，固定底栏不再覆盖页面末尾的表单或操作按钮。
- 移动端专注模式减少重复周状态、校准与策略信息，只保留行动区、今日检查和一个风险信号。
- Chromium 门禁覆盖 `320 / 390 / 768 / 1024 / 1440`，检查弹层、底栏、全部路由、横向溢出和桌面分组导航；每个路由另保存 `390px` 与 `1440px` 截图供复核。
- 桌面导航使用石墨色侧栏和清晰的分组入口，阶段、本周等数据留给总览与对应页面承载。
- 顶栏操作改为图标与 tooltip，官方边界说明回收到“资料核验”，默认专注模式隐藏重复的卡片解释文字。
- 字体切换为项目内打包的 Geist Variable 与 Noto Sans SC Variable，统一中文、拉丁字符和数字的字重与节奏。
- 应用常量集中到 `config/app-config.js`，阶段、考纲、学习路径、验收规则和资料配置迁入 `data/study-content.js`，`app.js` 不再保存大段纯内容数据。
- Lucide 图标集合与导航图标映射迁入 `ui/icon-registry.js`，避免入口文件重复维护图标导入和命名映射。
- 浏览器缓存读写、批量清理和不可用状态迁入 `infrastructure/browser-storage.js`，并覆盖允许与拒绝存储两类单元测试。
- `ui/view-render-coordinator.js` 接管页面渲染调度；路由切换只更新共享侧栏摘要和当前页面，总览的热力图、目标线与策略区不再被隐藏重绘。
- Supabase SDK 改为动态导入；没有历史云会话时首屏只加载本地适配层，不请求约 209 kB 的 SDK 分包。
- 顶栏图标样式集中到 `styles/components/toolbar.css`：桌面五个控件统一为 40 px，移动端只保留搜索、同步和账号三个 38 px 纯图标控件。
- Chromium 门禁遍历全部 10 个路由，并自动检查图标中心偏差、刷新按钮与状态外框中心、移动端无文字工具栏及无会话首屏不加载 Supabase SDK。
- 云端全量表查询按每页 500 行读取，避免 PostgREST 默认行数上限截断长期记录。
- 备份导入确认与取消、未登录同步反馈、重排时保留锁定任务由真实页面集成测试覆盖。

## 保留项及原因

以下模块当前不进入生产包（从 `src/main.js` 出发静态不可达），但不是可直接删除的垃圾文件：

- `src/core/router.js`、`src/core/state-manager.js`、`src/core/event-bus.js`
- `src/views/`（8 个视图模块）
- `src/infrastructure/sync-service.js`、`supabase-client.js`、`offline-cache.js`
- `src/utils/number.js`（只被 `state-manager.js` 与 `views/` 引用）
- 尚未由生产入口直接调用的部分 `src/domain/` 模块（`plan-generator`、`calibration-engine`、`review-queue`、`retrospective-engine`、`task-contract`、`source-registry`、`project-showcase`）

它们构成已测试的目标架构。直接删除会失去迁移成果；直接启动则会与 `app.js` 的状态、路由和同步重复绑定。完成接管前应保持“可测试但不启动”。

**这份清单的权威定义在 `scripts/verify-module-boundaries.mjs` 的 `PENDING_MIGRATION`，不是本文件。**
`npm run test:boundaries` 会从生产入口重算可达性并与该清单逐项比对，任何一侧漂移都会失败：

- 某个模块被生产模块引入（清单里仍写着"不进入生产包"）→ 失败；
- 某个模块不再可达却未登记 → 失败。

> **修正记录（2026-09-22）**：本文件此前把 `core/state-manager.js` 与 `core/event-bus.js` 列为"不进入生产包"，
> 该结论当时已被代码推翻——`ui/density-controller.js`（生产模块）导入了 `StateManager`，
> 使这两个模块连同 `utils/number.js` 一起进了 `app` chunk。`density-controller.js` 里
> 依赖 `StateManager` 的三个函数（`getDensityMode` / `setDensityMode` / `initDensityMode`）
> 当时只被一个单元测试调用，生产与迁移层都不用它们（各视图有自己的本地实现），已删除。
> 现在这三个模块确实不在生产包中，并由上述门禁锁定。详见 [AUDIT_2026-09-22.md](AUDIT_2026-09-22.md)。

## 建议的迁移顺序

1. 先统一状态契约。让 `StateManager` 读取当前 v3 数据结构，并为旧字段提供单向迁移适配，不再新增第二套字段名。
2. 路由 ID 集中化已经完成；下一步让 `router.js` 按 `route-contract.js` 接管 hash、焦点和历史记录，不再扩展 `app.js` 内的路由逻辑。
3. 先接管设置页。设置页写入面较小，适合验证新 StateManager、错误反馈和导入导出流程。
4. 再迁移今日、记录和复盘。这三页形成“计划 -> 执行 -> 记录 -> 复盘”的核心闭环，迁移时按整条流程验收。
5. 最后替换同步实现。只有新状态层稳定后，才让 `sync-service.js` 接管 `supabase-sync.js`，并删除旧实现。
6. 每接管一个页面，同时删除 `app.js` 中对应的 `bind*`、`render*` 和 HTML 静态骨架；不要只新增模块而保留双实现。

目标是让 `app.js` 最终只保留启动、依赖装配和跨页面工作流，不再保存页面模板或业务计算。

## 文件与样式治理

- JavaScript 文件继续使用 kebab-case；模块导出使用动作或领域名，避免 `utils2`、`new-*`、`legacy-*` 这类临时命名。
- 一个状态键、同步表名或路由 ID 只能有一个权威定义文件。
- 不再向 `base.css` 末尾追加“最终覆盖”。迁移页面时，把对应规则移入 `styles/views/<route>.css`，共享控件移入 `styles/components/`。
- CSS 拆分前不要批量删除看似重复的规则。当前部分相同规则用于在后置位置重新建立层叠优先级，必须按页面截图回归后逐段移除。
- 建议逐步引入 CSS cascade layers：tokens、base、layout、components、views、utilities、overrides；完成迁移后删除 overrides 层。
- 对新增模块设体积提醒：页面模块超过约 300 行、控制器超过约 200 行时，应检查是否混入数据转换、模板和事件三种职责。

## 前端设计验收与后续建议

当前桌面端的黑白灰基底、钴蓝强调色和“下一步行动”主视觉方向正确，主要问题是移动端发现性和信息重复，而不是视觉风格本身。

### P0：移动导航（已完成）

移动底栏已固定为 4 个高频入口加“更多”：总览、今日、周计划、记录、更多；“更多”打开现有命令面板，承载复盘、模考、资料、设置、路径、考点和全局操作。

隐藏路由会点亮“更多”并更新其无障碍标签。主内容使用独立滚动视口，底部留白和 `scroll-margin-bottom` 已保证输入框、提交按钮及错误焦点不会停在底栏后方。

### P0：专注模式信息量（已完成）

移动端专注模式已隐藏重复的周状态、详细校准、阶段建议和策略区，只保留下一任务、今日配套、到期复盘、今日检查与一个风险提示。平衡和详尽模式仍可查看完整信息，桌面布局保持不变。

### P1：记录闭环

完成任务后应提供就地快速记录，而不是要求用户再寻找记录表。建议任务完成反馈中直接出现分钟、题量、错因和“明日第一任务”的最小表单，并提供撤销入口。

重新生成计划前应展示差异预览：保留项、被替换项、顺延项和原因。这样可避免用户误覆盖已经开始的任务。

### P1：同步可信度

同步状态应明确区分“仅本机”“等待上传”“已同步”“冲突待处理”“同步暂停”，并显示最后成功时间。导入和恢复快照前展示数据计数差异，完成后提供短时撤销或恢复入口。

### P2：学习反馈

- 增加今日开始提醒与到期复盘提醒，默认关闭，由用户主动授权。
- 用一张可筛选趋势图替代多张重复数字卡，支持 7/14/30 天和科目筛选。
- 将考点证据与错题、复盘记录互相链接，让“已掌握”能够回溯到具体证据。
- 为底线日、正常日和加强日提供预估完成时间与超预算提示。

## 性能与验证建议

- Supabase SDK 已拆为独立动态分包；下一步将账号面板的认证交互继续从 `app.js` 抽到独立控制器，保持本地模式零云端开销。
- 当前已做到按当前路由渲染，但各页面代码仍包含在主应用分包中。视图接管后应继续使用动态导入，使今日、设置、记录等页面按路由加载。
- 浏览器门禁已经覆盖 320、390、768、1024、1440 宽度、全部 10 个路由、移动底栏遮挡、命令面板层级、图标几何中心和云 SDK 延迟加载；下一步增加对话框键盘焦点、离线恢复和导入失败场景。
- 每次拆分 CSS 或页面模板都保留桌面与移动截图对比；仅依赖 DOM 存在断言无法发现遮挡、过长页面和层级退化。

## 后续执行路线图

### P1-A：状态与设置页接管

让 `StateManager` 兼容读取当前 v3 数据并只执行单向迁移，然后由新设置页完成读写。验收标准是刷新、导入、重置和旧数据升级都只产生一次状态变更，生产入口不再保留对应的第二套字段与监听器。

### P1-B：任务到记录的快速闭环

任务完成后就地展开最小记录表单，只要求有效分钟、题量、错因和明日第一任务；保存时同时更新任务、记录与到期复盘，并提供短时撤销。验收标准是用户无需切换页面即可完成“执行 -> 留证据 -> 安排复盘”。

### P1-C：同步可信度

统一展示“仅本机、等待上传、已同步、冲突待处理、同步暂停”五种状态和最后成功时间。导入或恢复前显示记录数量差异；只有 StateManager 接管稳定后才替换旧同步实现，避免双写。

### P2：按流程拆分视图与样式

按设置、今日、记录、复盘的顺序，把对应模板、事件和样式一起迁入 `views/`、`ui/` 与 `styles/views/`。每完成一个页面就删除 `app.js` 和 `base.css` 中的旧实现，并通过五档宽度截图、单元测试和生产构建后再进入下一页。
