# 软微 420 学习台升级计划

版本：2026-10-09。依据是对生产链路、计划文档、样式层、登录与 Supabase 存储的审核，并吸收 Todoist、Things、Linear、Anki/FSRS、MyStudyLife 与番茄钟类产品里能提高完成率的能力。

本文件是执行契约。生产入口仍是 `index.html -> src/main.js -> src/app.js`。不引入 React，不并行启动 `router.js` 与 `sync-service.js`。

## 原则

- 一次只改一条用户流程，改完保留现有测试能识别的调用形状。
- 领域规则放在纯函数里；`app.js` 只负责装配、表单和渲染。
- 新页面样式放在 `src/styles/views/` 或 `src/styles/components/`，不再往 `base.css` 末尾堆覆盖。
- 动效只使用 `transform` 与 `opacity`，时长 150–220ms，缓动 `cubic-bezier(0.22, 1, 0.36, 1)`。`prefers-reduced-motion` 保留状态变化、去掉位移。
- 420 分、2200 小时和 `2027-12-25` 继续只作为内部校准，不写成录取或官方日期承诺。

## 现状判断

| 维度 | 判断 | 主要缺口 |
| --- | --- | --- |
| 架构 | 分层清楚，风险集中 | `app.js` 与两套样式仍是生产主体；`views/` 与 `sync-service.js` 已测试但未接管 |
| 前端 | 工作台方向正确 | 令牌写了两层；任务编辑与复盘失败用 `window.prompt` |
| 动画 | 偏弱 | 路由只有进入动画；进度条无限闪烁；`transition: all` 过多 |
| 功能 | 计划强、执行弱 | 勾选即用估算值回写记录，缺少就地证据、计时和撤销 |
| 计划 | 文档完整 | 睡眠、疲劳、当日档位没有进入每日记录，降载无法自动触发 |
| 可维护性 | 门禁强、文件过大 | 类型检查排除生产编排；迁移层与生产规则可能漂移 |
| 登录与存储 | 模型可靠 | 最后写入获胜；冲突表没有产品界面；`localStorage` 仍是整包主存 |

## 阶段

### 第一阶段：执行闭环

目标：完成一项任务后，用户不用离开当前卡片就能留下证据。

- 勾选后展开四字段：有效分钟、题量、一条错因、明日第一任务。保存后才把任务标完成，并写入当日记录与 D+1 复盘。
- 取消勾选仍按 `recordImpact` 回滚自动写入的数值。
- 重新生成今日计划前，列出保留、替换和原因；已锁定或已完成任务不覆盖。
- 每日记录增加睡眠小时、疲劳（1–5）和档位（底线 / 正常 / 加强）。
- 连续 3 天完成率低于 60%，或连续两晚睡眠不足 7 小时且有记录时，总览提示次日使用底线日。
- 顶栏同步文案使用五种用户语言：仅本机、等待上传、已同步、冲突待处理、同步暂停，并在有成功时间时附带最后同步时刻。

### 第二阶段：迁移层接管

目标：让 `app.js` 退回启动与跨页装配。本阶段不在同一次改动里替换生产路由和同步器，避免双写。

顺序：

1. `StateManager` 只读当前结构，旧字段单向迁移。
2. 设置页切到 `views/settings-view.js`。
3. 今日、记录、复盘按「计划 → 执行 → 记录 → 复盘」整条切过去。
4. 每切完一页，删除 `app.js` 中对应的 `bind*` / `render*` 和 `index.html` 静态骨架。
5. 状态稳定后，才用 `sync-service.js` 替换 `supabase-sync.js`。
6. 视图按路由动态导入。无云会话时首屏继续不加载 Supabase SDK。

`scripts/verify-module-boundaries.mjs` 的 `PENDING_MIGRATION` 仍是边界权威。接入某个模块时必须同时从清单删除它。

### 第三阶段：界面与动效

- 令牌以 `workspace.css` 的冷灰画布和钴蓝行动色为准。`base.css` 不再新增第二套颜色。
- 路由进入使用短位移和透明度；离开时先淡出再隐藏。
- 进度条只做宽度过渡，去掉无限 shimmer。
- 对话框使用 `scale(0.98)` 到 `scale(1)` 的短展开。
- 深色主题跟随 `prefers-color-scheme`，科目色不变，行动色仍只用于主操作。
- 命令面板继续承载低频页面；新增动作仍走现有按钮，不另建一套状态。
- 用页面内输入替换 `window.prompt`。

### 第四阶段：学习反馈

- 复盘提交四档：再次、困难、良好、简单。再次和困难缩短到下一天并累计失败次数；同一来源失败达到 3 次标为韭菜，总览提示减少新内容。
- 良好与简单按通过记录，并保留原来的间隔队列。
- 当前任务可开始 45 分钟会话。离开页面后剩余时间留在内存中的会话对象里，结束或放弃都写回同一张证据表单。
- 总览在热力图下增加 7 天趋势：每日总分钟、睡眠、完成率。
- 周日在今日计划上方出现单变量周审提示：只允许改总量、题型难度、复盘上限或一个弱项中的一个。
- 开始提醒与到期提醒默认关闭。用户打开设置里的开关后才请求通知权限。

### 第五阶段：账户与同步

- IndexedDB 继续做恢复镜像。`localStorage` 写入失败时，恢复副本仍保存最新整包，启动时取较新的一份。这一步先落地；把 IndexedDB 升成唯一主存要等设置页接管后再做，避免两条写入路径。
- 同步失败若包含冲突或重复键，状态进入「冲突待处理」，本机数据不丢。
- 登录保持邮箱密码和找回密码。通行密钥与魔法链接作为后续增量，不替换现有密码流。
- 快照仍由用户手动创建。恢复前继续展示差异；云端 `snapshots` 的保留上限留到同步器替换时做。

## 验收

每一阶段合入前跑 `npm test` 与类型检查。改动触及今日、记录、复盘或同步文案时，补一条能失败的契约测试。界面改动保持五档宽度门禁可运行。

第一阶段的人工路径：勾选任务 → 填写四字段 → 保存 → 记录页出现分钟与错因 → 取消勾选能回滚自动分钟 → 重新生成前能看到保留项。

## 明确不做

- 不把经验帖里的小时数写成必须刷满的定额。
- 不增加排行榜、断签惩罚或种树。
- 不在政治启动日（2027-07）之前自动排政治主线。
- 不把服务角色密钥、数据库密码或部署令牌写入仓库。
