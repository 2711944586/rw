## 0. 结论先说

**一句话**：这个项目在**内容深度和信息架构**上已经接近业内顶尖（对单用户备考系统这个品类而言），但**界面质感被"空间节奏不一致"和"同一信息在一屏内重复"拉低**，而这两者之所以反复出现，根因是**布局层没有单一事实来源**——CSS 里同一组件的网格定义有 20 余条互相竞争，改一处不知道另一处在哪。

| 维度 | 评分 | 判断依据 |
| --- | --- | --- |
| **内容 / 领域深度** | **A** | 路径页的 8 阶段里程碑、资料页的"产出/启用门/停用切换"、复盘页的证据化指标——这不是通用模板能长出来的，是真实备考经验的沉淀 |
| **功能完整度** | **B+** | 覆盖记录/任务/复盘/模考/考点/资料/同步/导出/离线状态，但有两处明确缺口（见 §3.1） |
| **信息架构** | **A-** | 10 个视图的分工清晰，密度三档（专注/平衡/详尽）是聪明的设计 |
| **界面 / UI** | **B** | 视觉语言克制统一，但**布局系统不可预测**，导致同一页面在不同视口/密度下表现不一致 |
| **排版** | **B+** | 层级清楚、数字用等宽、中文断行正常；扣分在若干卡片内文字与容器宽度不匹配 |
| **质感（细节完成度）** | **B-** | 主要被"卡片高度参差 + 大片空白 + 同屏重复"拉低，这三项恰好是最影响"高级感"的 |

**是否"全面"**：功能覆盖是全面的，但**"全面"不等于"顶尖"**。当前状态更准确的描述是：**深度已经到位，完成度还没到位**。

## 2. 这个项目做得好的地方（不要动）

- **路径页**是全站最强页：8 个里程碑卡片（编号 / 日期区间 / 标题 / 说明 / 验收线）信息密度高且节奏一致，"进入条件 + 本阶段过关"条把阶段门控讲清楚了。

## 3. 阻断"顶尖"的问题

### 3.1 功能缺口

| 缺口 | 现状 | 为什么影响"顶尖" |
| --- | --- | --- |
| **模考页没有趋势图** | 标题写着"模考趋势 近 5 套看方向，近 10 套看稳定性"，下面只有 5 个灰色胶囊和一条列表 | 有标题无图，是"承诺了却没兑现"。而且代码里已有 `renderTrendChart` / `renderRollingWindowChart` 可复用 |
| **总览页没有任何时间序列可视化** | 全是数字卡片 | 首页应当是"一眼看懂趋势"的地方，现在需要点进子页才能看到趋势 |
| **设置页是 13 个字段的一面墙** | 单个"计划设置"卡片里塞了 13 个字段，无分组 | 字段无单位（"工作日基础上限 180"是分钟吗？）、无分组，认知负担高 |

### 3.2 布局层没有单一事实来源（**这是最根本的问题**）

实测证据：

- `.focus-board` 的 `grid-template-columns` 在 390px 视口下有 **21 条规则参与竞争**，断点覆盖 1320 / 1180 / 1100 / 900 / 760 / 620 / 481 / 390，横跨 `base.css` 与 `workspace.css`。
- 移动端总览页两列塌不掉的根因：`workspace.css` 的 `@media (max-width: 620px)` 把 `.focus-board` 设成 `repeat(2, minmax(0,1fr))`，它在 `760px → 1fr` 之后，于是**在 390px 手机上反而胜出**。
- 模考页半屏空白的根因：`.panel.wide { grid-column: 1 / -1 }` 把趋势面板挤到第二行，第一行第二列（320–420px）整块空着；而按密度作用的规则带 `:not(#dashboard)`，其 ID 权重让页面级覆盖写不进去。

**为什么这比单个 bug 严重**：它意味着**每次改布局都在赌**。本轮我修了三处布局缺陷，三处都不是"写错了值"，而是"写对了但被别的规则盖住"。在这种结构下，界面不可能稳定达到顶尖——顶尖的前提是可预测。

### 3.3 空间节奏不一致（最影响"高级感"）

- **卡片高度参差**：总览页"420+ 内部校准线"卡片比同排邻居矮一半内容，底部约 90px 空白；"今日配套"卡片标题与内容之间也有明显空档。
- **大片空白**：模考页（已修）与考点页（已修）此前都有近半屏空白。
- **同屏重复**（已修两处）：考点页把免责句重复 13 遍、把分组列表整列重复；复盘页把 4 个指标在横幅和网格里各说一遍。
- **单位不统一**：总览页"本周状态 34.8 / 14h"——第一个数字没有单位。

### 3.4 语义与文案

- **风险指标直接显示颜色名**（已修）：`当前风险 绿色 / 红色 / 黄色`——把状态说成了色卡名，而且"绿色"是项目自己已经淘汰的配色词。
- **"学习曲线 99%"**（已修）：这个指标实际是"近 7 天 ÷ 前 7 天"的周环比比值，不是曲线；标签与数值语义不符。
- **设置页科目复选框视觉破损**（已修）：复选框被拉成 13×44，原生勾号与文字重叠。

## 8. 附带发现：版本控制曾中断（**已恢复**）

### 8.1 发现时的状态

```
$ cd D:/DATA/rw && git rev-parse --show-toplevel
D:/DATA                      # 仓库根不是项目目录，而是它的父目录
$ ls -d D:/DATA/rw/.git      -> 不存在
$ git log                    -> master 无任何提交
$ cd D:/DATA && git ls-files | wc -l   -> 1
```

`D:/DATA/.git` 里配着本项目的远端，但 `refs/` 是空的——本地 git 历史不可用。

### 8.2 恢复过程

远端**有完整历史**，所以是"重新关联"而不是"新建仓库"：

```powershell
cd D:\DATA\rw
git init -b main
git remote add origin https://github.com/2711944586/rw.git
git fetch origin                    # 下载对象
git update-ref refs/heads/main 370734de...   # 指向远端提交
git reset --mixed HEAD              # 用远端树填充索引，工作区文件不动
```

结果：`git status -sb` 显示 `## main...origin/main`，本地 3 个月的未推送工作全部以
diff 形式呈现，**没有任何文件被改动**。

### 8.3 根因：git 无法创建 `refs/remotes/<name>/` 嵌套目录

恢复过程中发现一个**环境级缺陷**，它才是当初引用丢失的原因：

| 引用路径 | `git update-ref` 结果 |
| --- | --- |
| `refs/heads/probe` | 成功 |
| `refs/tags/probe-tag` | 成功 |
| `refs/notes/probe` | 成功 |
| `refs/remotes/probe`（一层） | 成功 |
| `refs/remotes/origin/probe`（两层） | **失败**（退出码仍为 0，静默） |

- `git update-ref` 对两层的远端引用**静默失败**，对已存在的引用甚至会**删除**它。
- `git fetch` 会报告 `* [new branch] main -> origin/main`，但引用随后不存在。
- 手动 `mkdir -p .git/refs/remotes/origin && echo <sha> > .../main` **有效**——文件系统没问题，
  是 git 自己不创建那个中间目录。

**影响**：

- `git add` / `git commit` / `git push` **可用**（写的是 `refs/heads/*`，一层，正常）。
- `git fetch` **能下载对象但不能记录远端跟踪分支**；`git pull` 与"领先/落后"提示因此不可用。
- 每执行一次 `git fetch` 都会清掉手工恢复的 `refs/remotes/origin/main`，需要重新写回。

**建议**：这看起来是当前 PortableGit 构建（`C:/Users/13561/.workbuddy-ai/binaries/PortableGit/versions/1.2.0`，
`git version 2.55.0.windows.3`）的问题。装一个官方 Git for Windows 并把它放在 PATH 前面，
再验证 `git update-ref refs/remotes/origin/probe <sha>` 是否成功——这能一次性消除该缺陷。
